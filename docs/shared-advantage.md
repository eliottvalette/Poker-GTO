# Shared advantage approximation before the pilot

The migration replaces simulator-seat-specific neural regret functions with one
hero-centric advantage function per player-count track. It starts from main at
`9fda3f2` and preserves the hand engine, hand-chip-delta objective, external
sampling, outcome alternative, modest architecture and fresh fitting semantics.

```text
3-max: 1 AdvantageNetwork + 1 AveragePolicyNetwork
HU:    1 AdvantageNetwork + 1 AveragePolicyNetwork
```

Position is an input feature, not a model identity. Physical player IDs only select
the utility evaluated during a traversal and remain sample/coverage metadata.
Every advantage sample generated by any traverser in one track enters the same
uniform Algorithm R reservoir. The shared network is fitted once per iteration
from that pooled memory. Its regret-matched policy is used for any acting player.
Both advantage and average models remain freshly initialized from replay each
iteration. No optimizer continuation or average-policy scheduling change is made.

## Replay and budgets

| Track | Advantage capacity, total | Advantage byte budget | Strategy capacity | Strategy byte budget |
| --- | ---: | ---: | ---: | ---: |
| 3-max | 30,000 | 384 MiB | 10,000 | 128 MiB |
| HU | 20,000 | 256 MiB | 10,000 | 128 MiB |

Total retained capacity remains **70,000**, and configured replay byte budgets
remain **896 MiB**. The removed per-player capacity is not silently interpreted
as a new pooled capacity. Config version 2 explicitly records advantage capacity
and byte budget inside each track. The solver's programmatic default is 10,000
advantage samples times player count; an explicit `advantage_capacity` is now a
track total. Uniform pooling preserves the total sample limit, not separate
per-seat quotas. Generated/retained counts by source player remain diagnostics.

There are four modest networks (69,316 parameters combined), rather than seven.
The total replay population and two-epoch fitting work are preserved; this is a
statistical-sharing change, not a promised threefold runtime improvement.

## Strict hero-centric input

The earlier encoder did not consume `obs.hero`, but arbitrary identity still
entered through opponent-slot order and the order of synthetic initial STACK
history tokens. Merely sharing weights would have left equivalent views different.
Feature schema 2 fixes that source representation:

- Hero always occupies input slot 0.
- Opponents follow clockwise by public position (BTN/SB/BB or SB/BB).
- Stack, street-bet, contribution, folded, effective and initial-stack columns
  use that same order; the button index and all history actors follow it.
- Initial STACK tokens are sorted into that canonical order. These describe
  simultaneous initial state; actual betting and card-reveal chronology remains.
- Exact observable cards, suit normalization, legal masks and targets, and the
  complete current-hand public history remain present.

The raw lossless diagnostic/tabular observation stays unchanged at schema 3.
Python and browser apply the same projection. Renaming simulator seats and rotating
the ring's starting dictionary entry yields identical consumed tensors and neural
predictions, including after folds and on every street. Opponent/future cards
remain absent from model input.

## Persistence and consumers

Frozen snapshots hold one flat advantage state dict and explicit supported player
count. Workers validate root/count compatibility and never choose weights by
`obs.hero`. Central sample admission rejects foreign player-count data. Checkpoints
store one advantage model and one pooled advantage reservoir per track; resume
restores models, global reservoir counts/RNG, sampler state and metrics.

The incompatible per-seat snapshot/replay layout is retired, with no arbitrary
weight averaging or silent checkpoint conversion. Versions are config 2, raw state
3, feature 2, replay 6, runner checkpoint 2, average artifact 5 and ONNX manifest 4.
The architecture identifier is `cards8_numeric32_historyGRU32_head64_features2`;
layer widths and the 17,329 parameters per model are unchanged. ONNX manifests bind
`seat_normalization=hero_then_clockwise_positions`.

Updated source owners/consumers are `ml/deep_cfr.py`, `features/neural.py`,
`ml/model.py`, `ml/memory.py`, `ml/export_onnx.py`, `scripts/parallel_cfr.py`,
`training/{config,runner,checkpoint,evaluation,preflight}.py`, both training configs,
smoke/profiling helpers, and `ui/src/lib/{onnx-policy,poker/neural}.ts`.
Profiling helpers now measure the pooled 30k/20k populations and write separately
to `profiling/deep_cfr_shared_costs`, preserving earlier baseline measurements.
Future trained artifacts use `runs/deep_cfr_shared_pilot` (or the separately named
full-run template), avoiding replacement of the previous feature/model contract.

## Validation and bounded measurement

Validation passes 120 Python and 78 browser tests, Python compilation, TypeScript
checking, ESLint and diff checks.

The shared migration has regression coverage for one pooled fit across traversers,
seat/ring invariance of every consumed tensor and prediction, identical traversal
regrets under identity changes, preserved capacities, cross-track rejection,
checkpoint/RNG restoration and explicit rejection of the former seat layout.
Existing worker determinism, atomic failures, outcome sampling, current-hand
boundaries, model routing and dynamic-history PyTorch/ONNX parity still pass.

Two small real iterations ran with four traversals per player per track and eight
workers. They completed both shared fits, scheduled evaluation, atomic checkpoints
and both ONNX exports in about eight seconds. This is pipeline readiness evidence,
not a trained-policy quality claim. The complete record is
[shared-advantage-preflight.json](shared-advantage-preflight.json): four models,
about 3,990 accounted bytes/sample, 70k retained capacity, approximately 266 MiB
retained-replay projection, and 73,186 bytes per ONNX policy.

The earlier production-sized profile is a baseline for the retired layout. Its
25–40-minute pilot planning range is not an updated measured shared-model runtime;
sharing preserves data volume and changes learned policies/tree cost. No substantial
pilot, full training or GPU compute has been launched. Training remains importable
Python with no CLI, and no range model or online resolver is required.
